# 芯片手册与设计审查

## 证据顺序

1. 从用户指令或当前原理图元件中确定准确芯片型号；型号不明确时先追问，不能把位号、系列名或封装名当成完整料号。
2. 调用 `datasheet_evidence`，按任务选择主题。供电审查至少请求 `power`、`recommended_conditions`、`absolute_maximum` 和 `decoupling`；完整审查再加入 `pinout`、`clock_reset`、`interfaces`、`reference_circuit`、`layout`、`thermal_package`。
3. 证据片段不足以确认表格上下文、单位或条件时，用 `knowledge_read` 展开对应 `chunkId` 或 `documentId`。没有来源证据时明确标为“未从资料库确认”，不得用模型记忆补值。
4. 需要检查当前设计时，读取 `easyeda_schematic_components`、`easyeda_schematic_wires` 和 `easyeda_run_drc`。只有手册证据与 EDA 结构化事实能对应时，才能判定符合或不符合。

## 输出要求

- 先写审查对象：完整料号、位号、封装/版本线索及资料来源；无法确认的字段显式留空。
- 参数表至少包含“项目、最小值/典型值/最大值、单位、成立条件、来源”。不要把绝对最大额定值当作推荐工作条件。
- 引脚结论必须包含引脚编号或名称、功能、当前网络以及引用；无法从当前 EDA API 确认引脚网络时写“待人工核对”，不能猜测。
- 典型应用审查分成“手册要求”“当前设计观察”“结论”“建议”四列。DRC 通过不等于典型应用符合。
- 每个具体数值、引脚功能和参考电路要求都附文件相对路径、PDF 页码或文本行号及 SHA-256。多个版本冲突时并列展示，不能静默选一个。
- 结论只使用：`符合`、`不符合`、`证据不足`、`当前 EDA 数据不足`。建议与已确认事实分开。

## 选型比较

- 比较多个芯片时，每个完整料号分别调用 `datasheet_evidence`，使用相同主题和条件。
- 只比较有来源支持的参数，同时列出封装、温度等级、供货后缀或文档版本差异。
- 缺失参数不等于性能为零，也不能据此直接判负；标记为资料缺口。

本技能只读，不生成或执行设计写操作。
